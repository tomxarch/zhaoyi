# 交给外部模型批量翻译时（用户指定模型、文件太大时）

批量翻译很省钱：几十条一次请求，请求数能少一二十倍。但它也是“串格”的来源：模型合并两条、拆开一条、跳过一条，后面整串就错了一位。照译在这上面栽过跟头，下面每一条都是实测得来的。

## 怎么送
- **按结构打包**：同一张表的条目放一批，带上 `where`（表名、表头）作上下文；正文按连续段落打包。
- **批的大小**：每批 10 到 20 条、约 1500 字。免费小模型要更小的批。
- **短条目拿原文当键**：`{"Exigences minimales": "Exigences minimales"}`，要求输出时照抄键、值写译文。长段落用 `#1`、`#2` 编号。
- **不要让模型额外回显原文开头来做核对。** 小模型做不好这个格式。照译实测时请求数涨了 4 倍，还把原始 JSON 写进了文档。核对要自己来做，用 check.py。
- **提示里写明**：行业和文件类型；每条只给一种译法；保留标记和数字；术语表；“只输出 JSON”。

## 收回来
- 值必须是字符串。嵌套对象、列表套对象，或者看起来像 JSON 的，都算没给。**绝不把原始回复写进文件。**
- 有的模型会把回复再包一层 `{"blocks": {...}}`，先拆开再用。
- 一批里有两条以上过不了 check.py，或者整批解析失败，这一批就整个作废，拆成两半重翻；拆到只剩一条就单独翻。
- 单独翻的时候小模型也可能回 JSON：先从里面捞出这一条的译文，捞不到就留原文并标出来。
- 只缓存核对通过的译文；缓存的键里要带模型、目标语言、术语表和版本号。

## 模型的坑
- **会“思考”的模型要关掉思考**（Qwen3 系列、GLM、豆包）。比如加 `extra_body={"enable_thinking": false}`；不关的话一句要 40 多秒，看起来像卡死了。回复里的 `<think>…</think>` 要去掉。
- **遇到 429 限流**，按服务器给的时间等。免费额度每分钟只有十几次请求，不要多开并发。
- **参考费用**：用 DeepSeek 翻 16 页扫描检测报告，18 次请求，约 0.05 元；翻一份 300 多页的法语技术规范 Word，约 0.26 元。
- **小模型的局限**：免费的 9B 级模型术语常常不准（例：Disjoncteurs 被译成 Disruptors），格式也常不守规矩。正式交付用 DeepSeek 一类的模型，或者你自己翻。
