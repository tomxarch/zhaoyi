# 各格式怎么拆、怎么写回（zt.py 已经这样做）

这些逻辑都已经写进 zt.py。出问题时，先在这里查原因，再决定怎么处理。

## Word（.docx）
**拆分范围**
- 正文、页眉、页脚、脚注、尾注都会拆。
- 表格和文本框里的段落也会拆。文本框在 `mc:Fallback` 里的旧格式副本会跳过。

**格式标记**
- 一段里格式相同的连续文字算一组，组与组之间用 `<x1>…</x1>` 标记分开。
- 字距、字偶距、字宽、复杂文种字号这类差异会被忽略。原因是 PDF 转出来的 Word 每个词都带这些差异，不忽略的话，一句话会被拆成十几个标记，模型就容易原样返回、不翻。

**写回**
- 每组的译文写进该组第一个 run，其余 run 清空。
- 标记顺序变了，就按译文顺序重新排 run。
- 标记丢了，整段用第一组的格式。

**双语**
- 每段原文下面插一段译文。
- 带编号的段落并到同一段，免得多出一个编号。

**已知限制**
- 图片里的文字不翻。
- 域代码（目录、页码）不翻。
- 修订（track changes）里删除的文字不翻。

## PDF（按页自动分两种）
每一页先判断类型，同一个文件里两种页可以混在一起：

**电子版页**：文字能选中，没有铺满整页的大图。这种页做法是：
- 从页面内容里删掉原文字，图片、线条、表格框、底色都保留矢量原样；
- 在原位置用原来的字号、粗细、颜色写上译文。放不下时先换窄体，再缩字号；
- 表格格子里的文字留在格子里，原来是一行的尽量还是一行；
- 只有自动换行的行才合成一段；地址、电话、“Date:/编号：”这类标签行、项目符号行各自一条，不会并在一起；
- 中文用微软雅黑（粗体用雅黑粗体），中文译文里的英文名称、型号用 Arial；没有粗体字库时描边加粗；项目符号留在原位不翻；
- 输出的译文可以选中、搜索，放大也清晰。

**扫描页**：整页是一张图，或者字体没有编码、文字取不出来。这种页的做法是：
1. 转正横放的页面，纠正歪斜；
2. 把红、蓝印章和压在字上的黑色签名抠成单独图层；
3. 用 RapidOCR 认字，把行并成段落，表格文字归到各自的格子；
4. 用原背景色盖住原文，在原框里排译文：字号自动缩小，同一行表格统一字号；
5. 照片不认字；原本就是中英双语的标签不动；
6. 最后把印章、签名叠回最上层。

**强制按一种方式处理**：设环境变量 `ZT_PDF_MODE=text` 或 `ZT_PDF_MODE=scan`。

**限制**：
- 电子版页里画成图形的字（转曲的文字、图片里的字）不会被翻；竖排文字会让那一页按扫描页处理。
- 字体用 Arial 或系统无衬线字体，衬线体原文（宋体、Times 一类）会换成无衬线体。
- 扫描页 `limit` 小的短标注，用简洁但完整的说法。

## Excel（.xlsx）
- 直接改共享字符串表和单元格内联文字。公式、数字、图表、格式都不动，拼音注音也不翻。
- 工作表名也翻：最多 31 个字符，不能有 `\ / ? * [ ] :`，不能重名。公式、名称和图表里引用的表名会跟着改。
- 旧版 .xls 要先另存为 .xlsx。

## 其他格式
- **HTML**：翻文本节点和 alt、title、placeholder 属性，`lang` 改成目标语言。不翻代码、脚本和样式。
- **ePub**：每章按 HTML 处理，元数据里的语言也会改。
- **Markdown**：代码块、行内代码、链接地址、图片地址都原样保留。
- **JSON**：只翻值，不翻键。`{name}`、`%s` 这类占位符必须保留。
- **TXT**：保留原编码和每行前后的空白。
